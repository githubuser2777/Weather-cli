### Phase 1: Unit Testing & Robustness

**Goal:** Establish unit testing coverage for all core packages in `internal/` using the standard Go `testing` library. Mock HTTP endpoints using `net/http/httptest` to test geocoding, IP location detection, and weather fetches. Ensure visual layout formatting handles long city names without breaking alignment.
**Requirements:**

- Implement mock HTTP server tests using `net/http/httptest` for `location.DetectLocation` and `weather.FetchWeather` / `weather.GeocodeCity`.
- Implement table-driven tests for `weather.decodeWeatherCode` and display formatting functions in `internal/display`.
- Add test coverage for configuration load/save/fallback logic in `internal/config`.
- Dynamically calculate CLI box-width formatting inside `internal/display` so that long city names do not break the right border alignment.

**Depends on:** Phase 0
**Plans:** 1/1 plans complete

### Phase 2: Local Cache & Config Settings

**Goal:** Implement JSON-based weather API response caching (10-minute TTL) at `~/.weather-cli/cache.json` and support configuration command line flags to display/set preferences.
**Requirements:**

- Implement a lightweight local caching mechanism for weather API queries. If cached within 10 minutes for the same coordinates, return the cached result.
- Implement `--config-show` flag to display currently stored default settings.
- Implement `--config-set` flag in format `<key>=<value>` to set preferences (e.g. `weather --config-set city=Hanoi` or `weather --config-set unit=fahrenheit`).
- Write comprehensive unit tests for cache and configuration extensions.
